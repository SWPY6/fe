# 주식 API 모킹의 구조와 근거

이 작업의 목적은 Orval·Faker·MSW의 자동 생성 흐름을 유지하면서, 주식 데이터의
이름·가격·값 사이의 관계를 일관되게 만드는 것이다. 요청에서 정한 방향은 핸들러마다
응답 데이터를 작성하거나 실제 종목을 배열에 나열하지 않고, 재생성 후에도 커스텀 규칙을
유지하는 것이다. 관계 계산을 확장할 때 수정 위치와 책임을 알 수 있어야 한다.

## 생성 규칙과 관계 계산을 나눈 이유

OpenAPI의 `number`만으로는 그 값이 주가인지, 거래량인지, 등락률인지 알 수 없다.
따라서 [orval.config.ts](../../../orval.config.ts)의 `override.mock.schemas`에서
실제 스키마와 필드를 지정해 Faker 생성 규칙을 연결한다. 예를 들어
`StockQuoteResponse.price`에는 가격 범위를, `Indicators.volume`에는 거래량 범위를
지정한다. 필드 이름만으로 모든 응답에 같은 규칙을 적용하지 않는다.

이 필드별 콜백은 다른 필드 값을 인자로 받지 않는다. 생성된
[api.msw.ts](../generated/api.msw.ts)에서도 각 콜백은 독립적으로 호출된다.
가격 범위를 지정하는 것과 `등락폭 = 현재가 − 전일 종가`를 만족시키는 것은 별도 작업이다.
필드의 기본 생성은 Orval 설정이 맡고, 여러 값이 함께 결정되는 관계는 아래 모듈이 맡는다.

| 위치                       | 책임과 분리 이유                                                                                                                      |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| [stock.ts](stock.ts)       | 종목의 식별 정보와 일봉에서 목록·시세·차트를 만든다. 같은 종목의 현재가와 차트 종가가 함께 결정되므로 한 모듈에 둔다.                 |
| [industry.ts](industry.ts) | 전체 종목을 받아 산업 평균·순위·대표 종목·뉴스 카드를 계산한다. 산업 응답들이 같은 모집단과 순위를 사용하도록 함께 계산한다.          |
| [market.ts](market.ts)     | 시장별 통화·시간대·기준일과 지수·환율을 구성한다. 지표의 현재값·등락폭·등락률을 함께 계산하고 두 시장 탭이 같은 환율 카드를 사용한다. |
| [browser.ts](browser.ts)   | 요청 파라미터를 해석하고, 계산 결과를 Orval이 생성한 `get…MockHandler`에 연결한다. HTTP 경로 정의는 생성된 핸들러가 담당한다.         |

파일을 나눈 기준은 화면의 차트·카드 종류가 아니라 **함께 계산되어야 하는 데이터**다.
응답 타입은 [api.schemas.ts](../generated/api.schemas.ts)를 사용한다.

## 생성할 때와 요청받을 때의 흐름

`pnpm api:generate`는 다음 순서로 실행된다.

```text
openapi.json + openapi.overlay.yaml
  → openapi.generated.json
  → Orval + orval.config.ts의 Faker 규칙
  → generated/의 요청 함수·타입·데이터 생성 함수·MSW 핸들러
```

[Overlay](../openapi.overlay.yaml)는 원본 OpenAPI에 적용할 변경을 별도 파일로 보관한다.
Orval은 Overlay를 적용한 결과를 입력으로 읽는다. 커스텀 내용은 Overlay·Orval 설정·이
디렉터리의 코드에 있고, 생성 명령이 다시 쓰는 대상은 `openapi.generated.json`과
`generated/`다. 이것이 재생성 후에도 커스텀 내용을 유지하는 방식이다.

`pnpm dev:mock`으로 실행하면 다음 순서로 데이터가 연결된다.

1. `stock.ts`가 `getStockListItemMock()`으로 기본값을 생성하고, 국가·산업·일봉 계산을
   적용해 공유 종목 목록인 `stocks`를 구성한다.
2. `browser.ts`가 `industrySnapshot(stocks, country)`를 호출해 국가별 산업 데이터를
   계산한다. 시장 요약은 `market.ts`의 `marketSummary`를 사용한다.
3. MSW가 요청을 받으면 `browser.ts`의 응답 콜백이 이 데이터를 조회하거나 계산한다.
   목록·시세·산업 카드를 요청할 때마다 종목을 새로 생성하지 않는다.

## 관계 계산의 입력과 결과

| 계산                 | 입력 → 결과                                        | 유지해야 하는 관계                                                                                                                          |
| -------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `stockHistory`       | 종목의 ID·현재가·거래량과 시작일 → 일봉            | 종목 ID를 시드로 사용한다. 짧은 구간과 긴 구간의 겹치는 일봉이 같고, 마지막 종가가 현재가와 같다.                                           |
| `stocks` 구성        | 생성된 기본값과 최근 일봉 → 종목별 시세·지표       | 전일 종가로 등락폭·등락률을 계산한다. 시세의 OHLC·거래량과 마지막 일봉의 값이 같다.                                                         |
| `stockList`          | 국가·검색어·산업·정렬·페이지 조건 → 목록           | 공유 종목을 필터링하고 정렬한 뒤 페이지를 자른다. `total`은 페이지를 자르기 전 개수다.                                                      |
| `stockChart`         | 종목·시작일·종료일·봉 단위 → 차트                  | 요청 구간의 일봉을 합산한다. 첫 시가·최고가·최저가·마지막 종가·거래량 합계를 사용한다.                                                      |
| `industrySnapshot`   | 전체 종목·국가 → `flows`, `news`, `trends(filter)` | 전체 산업의 순위를 먼저 계산한다. 필터로 일부 산업만 반환해도 원래 순위를 유지한다. 대표 종목은 같은 종목 데이터에서 시가총액순으로 고른다. |
| `marketSummary` 구성 | 지표별 기준값과 변동률 → 국내·해외 지표            | 현재값에서 등락폭·등락률을 계산한다. 국내·해외의 `USD_KRW` 값이 같다.                                                                       |

산업 평균은 종목의 가격과 전일 종가로 구한 반올림 전 등락률을 사용한다. 뉴스 카드의
산업 선정도 같은 산업 통계를 사용하며, 등락 방향과 직전 20일 평균 대비 거래대금 조건을
적용한다. 각 API에서 평균이나 순위를 따로 생성하지 않는다.

## API 조건의 근거

모킹 값의 범위와 API가 정한 조건을 구분한다. 현재 코드가 참조하는 근거는 다음과 같다.

| 조건                                                            | 근거와 적용 위치                                                                                                                                                                                           |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 산업별 대표 종목 0~4개, 전체 산업 기준 순위                     | [산업 동향 명세](../docs/api-v1-industries-trends.md). 배열 개수는 Overlay, 선정과 순위는 `industry.ts`에 반영한다.                                                                                        |
| 산업 흐름의 대표 종목 0~2개, 미계산 시각은 `null`               | [산업 흐름 명세](../docs/api-v1-industries-flows.md). 타입·배열 조건은 Overlay, 집계는 `industry.ts`에 반영한다.                                                                                           |
| 뉴스 카드 순서와 개수, 카드별 기사 0~1개                        | [산업 뉴스 명세](../docs/api-v1-industries-news.md). 기사 개수는 Overlay, 카드 선정은 `industry.ts`에 반영한다. 거래대금 선정 조건은 [OpenAPI](../openapi.json)의 `/api/v1/industries/news` 설명을 따른다. |
| 국내·해외 시장의 지표 구성과 공통 환율                          | [시장 요약 명세](../docs/api-v1-markets-summary.md). `market.ts`에 반영한다.                                                                                                                               |
| 시세·등락률·OHLC·거래량 비율의 관계                             | [주식 시세 명세](../docs/api-v1-stocks-{stockId}-quote.md). `stock.ts`에서 같은 종목의 일봉과 현재가를 바탕으로 계산한다.                                                                                  |
| 차트의 `from/to/interval`, 최대 5년 구간, 확정 봉의 평균 거래량 | [주식 차트 명세](../docs/api-v1-stocks-{stockId}-chart.md). 파라미터 해석은 `browser.ts`, 봉 계산은 `stock.ts`에 반영한다.                                                                                 |
| 종목 목록의 필터·정렬·페이지 조건                               | [Overlay](../openapi.overlay.yaml)에 정의된 `/api/v1/stocks`와 `StockListItem`. 이 항목에는 `x-contract-source: frontend-proposed`가 붙어 있다.                                                            |

## 현재 모킹을 구성하기 위해 선택한 값

아래 항목은 구현 과정에서 정한 가상 데이터 구성 방식이다. 사용자 요구나 API의 제약을
뜻하지 않는다. 값을 조정할 때는 각 항목의 위치에서 변경한다.

| 선택            | 현재 구현과 위치                                                                                                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 종목 수         | `stock.ts`의 `stocksPerIndustry = 8`. 국가·산업은 생성된 enum을 순회하며, 현재는 2개 국가 × 9개 산업 × 8개 종목이다.                                                                                     |
| 재현 방식       | 기본 데이터 시드는 `260930`, 일봉 시드는 종목 ID다. 같은 기준일과 생성 규칙에서 데이터를 재현한다.                                                                                                       |
| 종목명과 코드   | 한국은 Faker 한국어 이름 + 산업명, 6자리 숫자 코드다. 미국은 Faker 회사명과 중복 없는 4자리 영문 코드다. `stock.ts`에서 구성한다.                                                                        |
| 가격과 거래량   | 기본 범위는 Orval 설정에 있다. 한국 가격은 `stock.ts`에서 생성값을 정수로 반올림한 뒤 100배 한다. 일봉 변동 폭도 `stock.ts`에 있다.                                                                      |
| 시간과 일봉     | `market.ts`에서 실행 시점의 UTC 날짜 이전 마지막 평일을 기준일로 정한다. `stockHistory`는 그 기준일에서 과거 방향으로 최대 5년의 평일 일봉을 생성한다. 공휴일과 장중 변동은 현재 계산에 포함하지 않는다. |
| 거래대금과 평균 | `stock.ts`에서 OHLC 평균 가격 × 거래량으로 거래대금을 추정한다. 거래량 비율과 산업 선정용 평균 거래대금은 직전 20개 일봉으로 계산한다.                                                                   |
| 뉴스·유의 종목  | `industry.ts`는 홀수 순위 산업에 모의 기사 1건을 넣는다. `stock.ts`는 각 산업 첫 종목을 유의 종목으로 지정한다. 기사 유무와 유의 종목 필터를 표현하기 위한 현재 데이터 배치다.                           |

## 이어서 작업할 때의 수정 기준

독립적인 필드의 생성 범위를 바꾸면 `orval.config.ts`를 수정하고 `pnpm api:generate`를
실행한다. 현재 응답에서 그 필드를 관계 계산으로 덮어쓰는 경우에는 해당 모듈도 확인한다.
예를 들어 시세의 `changeRate`는 Orval의 기본 생성값 대신 `stock.ts`의 계산 결과가 쓰인다.

여러 필드나 응답 사이의 관계를 추가하면 그 입력 데이터를 소유한 모듈에서 계산한다.
종목의 새 지표는 `stock.ts`, 전체 종목을 집계하는 산업 지표는 `industry.ts`가 수정 지점이다.
기존 종목을 참조하는 응답은 같은 `stocks`에서 값을 가져오고, 요청 연결은 `browser.ts`의
생성된 핸들러 콜백에 둔다.

변경 후에는 `pnpm api:generate`와 `pnpm typecheck`로 생성 코드와의 연결을 확인한다.
요청 동작은 `pnpm dev:mock`에서 같은 종목의 목록·시세·차트 값, 산업 필터 전후의 순위,
기간이 겹치는 차트의 일봉을 비교하면 확인할 수 있다.
