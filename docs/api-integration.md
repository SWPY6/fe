# API 계약과 프론트 연동

2026-09-30 기준. 이 문서는 API가 확정되지 않은 상태에서 화면 개발을 진행하기로 한 이유와, 서버 계약이 나왔을 때의 수정 원칙을 기록한다.

## 현재 상황

- 네 개 화면은 아직 상수 데이터로 그린 디자인 데모다. 화면에서 필요한 값은 [화면 데이터 요구](./frontend-data-requirements.md)에 정리돼 있다.
- 백엔드 코드 사본에서 종목 시세 조회 컨트롤러는 확인했다. 종목 차트는 백엔드 명세 문서가 있지만 컨트롤러는 확인되지 않았다. 배포 상태는 확인하지 않았다.
- 나머지 화면용 API 경로와 응답은 프론트가 제안한 작업용 계약이다. [API 요구사항](./api-requirements.md)의 후보 경로도 서버 구현을 뜻하지 않는다.
- 요청 함수와 개발용 MSW 응답은 생성돼 있고, 화면별 조회·변환 코드도 작성돼 있다. 페이지는 아직 그 조회 코드를 사용하지 않는다.

## 선택한 방식

API의 작업용 계약은 [OpenAPI 명세](../src/api/openapi.json)에 둔다. 각 operation의 `x-contract-source`는 계약의 근거를 구분한다.

| 값                  | 의미                                             |
| ------------------- | ------------------------------------------------ |
| `backend-spec`      | 백엔드 문서에 근거한 명세. 배포·동작 확인은 별개 |
| `frontend-proposed` | 화면 개발을 위해 프론트가 제안한 명세            |

이 명세에서 요청 함수·타입·MSW 응답을 생성한다. 개발 중 화면도 생성된 요청 함수를 호출한다. 현재 MSW 기본 응답은 명세의 example을 사용하므로 필터·페이지·저장 상태에 따라 달라지지 않는다.

화면별 `queryOptions`의 `queryFn`은 요청을 담당하고, `select`는 응답을 화면에서 쓸 값으로 바꾼다. 서버 필드나 API 구성이 달라져도 화면에 필요한 데이터의 의미가 같다면 이 변환 지점에서 맞춘다. 공통 변환은 여러 화면에 같은 규칙이 생겼을 때 검토한다.

현재 공통 HTTP 처리는 성공 응답의 `data` 봉투를 검사하고 오류를 `ApiError`로 분류한다. 성공 응답의 내부 필드는 런타임에 검증하지 않는다.

## 화면 연결

1. 화면에 필요한 값과 로딩·오류·빈 결과·결측 상태를 정한다.
2. 해당 API의 출처와 계약을 확인한 뒤, 이미 작성된 화면별 `queryOptions`의 호출과 `select` 결과를 대조한다.
3. 페이지를 조회 결과에 연결한다. 산업 평균·전체 순위처럼 전체 시장 데이터가 필요한 값은 서버가 제공해야 한다.

### 종목 식별자

현재 상세 URL의 `code`에는 종목코드가 들어간다. 백엔드의 `stockId`는 별도 숫자 식별자이며 시세·차트 API의 경로 변수다. 상세 화면을 연결하기 전에 다음 계약을 정해야 한다.

- 목록에서 상세로 이동할 때 `stockId`를 얻는 방법
- 종목코드로 직접 들어온 주소에서 종목을 찾는 방법
- 시장이 다른 동일 ticker를 구별하는 방법
- 상세 URL을 유지하거나 변경할지에 대한 제품 결정

## 실제 서버 API가 나오면

1. 서버의 경로·메서드·필드·결측·오류 코드·인증·시각·페이지 규칙을 작업용 계약과 대조한다.
2. OpenAPI의 해당 operation, schema, example과 `x-contract-source`를 검증된 계약에 맞게 수정한다.
3. `pnpm api:generate`로 요청 함수·타입·MSW 핸들러를 다시 생성한다.
4. 영향을 받는 화면의 `queryOptions` 호출과 `select` 변환을 수정한다. 화면에서 쓰는 값의 의미가 달라질 때만 페이지도 수정한다.
5. MSW 응답과 필요한 필터·페이지·저장·오류 시나리오를 갱신한다. API 주소와 인증 방식도 실제 계약에 맞춘다.
6. `pnpm check`, 화면 테스트, 실제 서버 응답으로 요청·오류·빈 결과를 확인한다.

산업 평균·순위, 거래량 급증 판정, 변동 배경, 알림 발송은 서버가 제공하거나 수행해야 한다. 필요한 데이터가 빠졌다면 서버 계약을 조정하거나 화면에 결측 상태를 표시한다.
