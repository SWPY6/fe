# 기능정의서·데모 기준 API 요구사항

이 문서는 2026-09-28 시점의 후보 목록이다. 이후 정해진 프론트 연동 방식과 현재 명세 상태는 [API 계약과 프론트 연동 방향](./api-integration.md)을 먼저 확인한다.

작성 기준: 2026-09-28. [기능정의서 v2 원문](./wiki-feature-spec.md), [GitHub 위키](https://github.com/SWPY6/fe/wiki/%EA%B8%B0%EB%8A%A5%EC%A0%95%EC%9D%98%EC%84%9C), [PLOUTOS Prototype v3](https://ploutos-requirements-qa.summmmmer-k.chatgpt.site/), [종목 시세 임시 계약](../src/api/docs/api-v1-stocks-{stockId}-quote.md). 데모의 숫자·뉴스·로그인은 디자인용 예시다.

이 문서의 URL은 백엔드와 논의하기 위한 **API 후보**다. 실제 경로·응답 형태가 확정된 것은 `GET /api/v1/stocks/{stockId}/quote` 하나뿐이다. 다른 후보의 존재나 구현 상태를 뜻하지 않는다. 기능 요구와 데이터 소유권을 먼저 정하고 경로와 필드명은 계약에서 맞춘다.

`market`, `period`, `view`, `sort`의 실제 값과 API 봉투·오류 형식은 받은 계약에 맞춰 정해야 한다. A1의 산업/미리보기 내용은 A2/A4의 축약 표현이며, 별도 화면용 계산 규칙을 만들지 않는다. A4의 `q`를 비워 목록으로 쓰고 채워 검색으로 쓰는 방식은 후보일 뿐이다. **A5와 A8은 별도 엔드포인트일 필요는 없다.** 필요한 필드를 A6·A4·A9 등에 합칠 수 있다. 중요한 것은 종목의 산업/시장 정보와 근거 있는 변동 배경을 받을 수 있는 계약이다.

위키의 용어 표에만 있는 ‘아침 브리핑’과 ‘과거 조회’는 대응 RQ와 데모 화면이 없어 이번 API 목록에 넣지 않았다. 거래 실행·투자 추천도 위키가 제공하지 않는 기능으로 명시한다.

## API 계약에서 먼저 확정할 값

1. **시장과 시각**: 국내/해외 식별값, 기준 시각·시간대·통화, 장중 실시간/지연/마감 구분, 시세·산업 평균·종목 목록이 같은 기준 시각을 쓰는 방법.
2. **목록 계약**: A4 검색의 양 시장 범위, 필터·정렬·페이지 크기와 최대 결과, 정렬 동률 처리, 변동 배경의 제공 방식. 위키 RQ-0708은 `100개/페이지·최대 5페이지`이고 데모는 `20개/페이지·최대 100개 표시`다. 기능정의서를 기준으로 협의해야 한다.
3. **산업 산정**: 산업 ID/9개 분류, 평균 등락률의 원값·대상 수·거래대금 변화율, 결측/거래정지/미매핑 제외. 위키 RQ-0701은 기타·미분류 종목을 전체 목록에 포함하고 RQ-1111은 모든 종목을 9개 산업에 분류한다. 현재 프론트 문서의 적용 기준은 [도메인 모델 초안](./domain-model-draft.md)처럼 전체 목록에는 포함하고 산업 카드 계산에서는 제외하는 것이다.
4. **핵심 뉴스·변동 배경**: 선정 결과를 서버가 주는지, 근거 자료 ID/URL·시간창·요약 문구를 어떻게 제공하는지. `변동 이유`를 프론트가 시세값만 보고 만들어서는 안 된다.
5. **차트**: 시장 지표에도 캔들용 OHLC가 실제로 제공되는지, 거래량 평균선이 단일 기준값인지 날짜별 20일 이동평균인지, 결측 거래일의 표현.
6. **개인화**: 인증 방식, 핀 순서 저장, 종목별 알림 개수/중복 정책, 알림 평가 주기·발송 수단, 도착 목록 보관 범위. 위키에는 발송 수단과 읽음 기능이 명시되지 않았다.
